<feature>
  <name>Car Charging Schedule Algorithm</name>
  <files>
    custom_components/energy_manager/car_charging_scheduler.py
    tests/test_car_charging_scheduler.py
  </files>
  <behavior>
    build_car_charging_schedule() selects the cheapest hourly slots before a departure
    deadline to charge from current SOC to target SOC.

    Algorithm:
      1. energy_needed_kwh = (target_soc - current_soc) / 100.0 * battery_capacity_kwh
      2. hours_needed = energy_needed_kwh / max_charge_power_kw
      3. Filter price_slots to those where slot.start >= now AND slot.end <= departure_time_utc
      4. Sort available slots by price ascending
      5. Select cheapest ceil(hours_needed) slots
      6. Build chronological schedule with "charge" or "idle" actions

    Data structures (frozen dataclasses, no HA imports):
      - CarScheduleSlot(start: datetime, end: datetime, price: float, action: str)
        where action is "charge", "idle", or "solar_charge"
      - CarScheduleResult(schedule: list[CarScheduleSlot], charging_slot_count: int,
        energy_needed_kwh: float, hours_needed: float, current_action: str,
        is_preliminary: bool)

    Cases (input -> expected output):
      - SOC 20%, target 80%, 77kWh battery, 11kW charge: needs 46.2 kWh = 4.2h -> 5 cheapest slots
      - SOC 80%, target 80%: needs 0 kWh -> all idle, current_action="idle"
      - SOC 80%, target 70% (already above target): needs 0 kWh -> all idle
      - No available slots before departure: empty schedule, current_action="idle"
      - max_charge_power_kw = 0: returns empty result (division guard)
      - fallback_mode=True: selects cheapest half of available slots (not exact N)
      - is_preliminary=True passed through: marks schedule as based on incomplete data
      - Slots not in [now, departure] window are excluded
      - current_action derived from which slot contains `now` (charge if in selected slot, else idle)
      - Solar charge: if solar_surplus_available=True, mark applicable slots as "solar_charge"
  </behavior>
  <implementation>
    Follow the Phase 2 battery_scheduler.py structure:
    - Module docstring explaining algorithm, no HA imports
    - Frozen dataclasses for input/output types
    - Single public function build_car_charging_schedule()
    - Helper functions prefixed with underscore
    - math.ceil for rounding hours up to whole slots
    - All datetimes are UTC-aware (datetime with timezone.utc)

    Key details:
    - Use math.ceil to round hours_needed to whole slots (each slot = 1 hour)
    - current_action: find the slot where start <= now < end, return its action
    - If now is not within any scheduled slot, current_action = "idle"
    - Fallback mode: sort by price, take cheapest len(available) // 2 slots
    - Solar charge: if solar_surplus_available flag is True AND a slot falls within
      daylight hours (can use a simple heuristic or just mark all charge slots as
      solar_charge when the flag is set -- Phase 5 handles actual PV routing)
    - is_preliminary: pass-through flag; the coordinator determines if tomorrow's
      prices are missing and sets this

    For tests, follow the Phase 2 test pattern:
    - Use importlib MetaPathFinder stub if needed for HA-free imports
    - Create helper to generate price slot dicts
    - Test each case from the behavior section above
  </implementation>
</feature>
