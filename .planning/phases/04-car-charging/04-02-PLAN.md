<objective>
Create CarChargingCoordinator (one per car subentry), CarEntity base class, fallback detection logic, and wire into __init__.py.

Purpose: The coordinator is the HA-side bridge between the pure scheduler (Plan 01) and the entity layer (Plan 03). Each car gets its own independent coordinator that chains to PriceCoordinator, reads car-specific sensors, and produces CarChargingData. The CarEntity base provides per-car device registration so each car appears as a separate device in HA. Fallback detection (EV-08) activates off-peak charging when a charger reports a car connected but no configured car's SOC is updating.

Note on EV-05/EV-06 (auto-detect Skoda/VW, manual car mapping): These requirements were fully implemented in Phase 1 via CarSubentryFlowHandler in config_flow.py. That flow already calls find_car_integrations() for auto-detection (EV-05) and provides manual entity selectors as fallback (EV-06). Phase 4 consumes subentry data created by that flow -- no additional config flow work needed.

Note on solar_surplus_available: In Phase 4, this parameter is always passed as False to build_car_charging_schedule(). The scheduler supports the flag as a pass-through so Phase 5 (Easee Charger Control) can wire actual PV surplus detection via PVHysteresisTracker. Phase 4 does NOT read PV power or compute surplus for EV charging.

Output: CarChargingCoordinator class in coordinator.py, CarEntity base in entity.py, updated EnergyManagerData, per-subentry creation loop in __init__.py.

    **coordinator.py** -- Add fallback detection method to CarChargingCoordinator:

    `_detect_fallback_needed(self) -> bool`:
    Implements EV-08 (fallback charging for unrecognized vehicles). Returns True when the Easee charger reports a car is connected but this coordinator's car SOC has not updated recently (stale for >FALLBACK_STALE_THRESHOLD_MINUTES). The heuristic:
    1. Read self._charger_status_entity state (same entity used by EMSCoordinator._is_car_plugged_in)
    2. If charger is not in a connected state (awaiting_start, charging, ready_to_charge, car_connected), return False
    3. If self._soc_last_updated is None (never received a SOC reading), return True (unrecognized car)
    4. If (utcnow() - self._soc_last_updated) > FALLBACK_STALE_THRESHOLD_MINUTES * 60 seconds, return True
    5. Otherwise return False (recognized car with recent SOC)

    Note: Each car coordinator checks its own SOC staleness independently. If ANY configured car has a recent SOC update, that car's coordinator uses normal mode. A car whose SOC is stale uses fallback for itself.
