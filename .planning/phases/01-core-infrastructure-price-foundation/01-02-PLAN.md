Create `config_flow.py` implementing the multi-step wizard per user decisions. Import constants from `const.py`, auto-detection from `auto_detect.py`, and Nordpool detection from `nordpool_adapter.py`.

**EnergyManagerConfigFlow(ConfigFlow, domain=DOMAIN):**
- `VERSION = CONFIG_VERSION` and `MINOR_VERSION = CONFIG_MINOR_VERSION` (from const.py)
- `__init__`: Initialize `self._data: dict[str, Any] = {}` for accumulating step data

**Step 1 -- `async_step_user` (Price Source):**
- Call `find_all_nordpool_sensors(self.hass)` to get available sensors
- Build schema with `EntitySelector(EntitySelectorConfig(domain="sensor"))` for Nordpool sensor selection
- If auto-detected sensors found, use first as `suggested_value` via `add_suggested_values_to_schema`
- On submit: validate entity exists, call `detect_nordpool_type()` to determine variant
- If type is "unknown", set `errors["base"] = "nordpool_not_found"`
- On success: store `CONF_NORDPOOL_SENSOR` and `CONF_NORDPOOL_TYPE` in `self._data`, proceed to `async_step_modules`
- Add `await self.async_set_unique_id(DOMAIN)` + `self._abort_if_unique_id_configured()` at start to enforce single instance

**Step 2 -- `async_step_modules` (Module Selection):**
- Show `BooleanSelector()` checkboxes for `CONF_BATTERY_ENABLED` and `CONF_EV_ENABLED`
- On submit: store module toggles in `self._data`
- If battery enabled: proceed to `async_step_battery`
- Else if EV enabled: proceed to `async_step_ev`
- Else (neither enabled): proceed to `_create_entry()` -- integration still works as price-only backbone

**Step 3 -- `async_step_battery` (Home Battery Config -- conditional):**
- Call `find_sigenstor_entities(self.hass)` for auto-detection
- Schema: `vol.Optional(CONF_SOC_ENTITY): EntitySelector(EntitySelectorConfig(domain="sensor"))`, `vol.Optional(CONF_BATTERY_POWER_ENTITY): EntitySelector(EntitySelectorConfig(domain="sensor"))`
- Pre-fill with auto-detected values via `add_suggested_values_to_schema`
- On submit: store battery config in `self._data`
- If EV enabled: proceed to `async_step_ev`
- Else: proceed to `_create_entry()`

**Step 4 -- `async_step_ev` (EV Charging Config -- conditional):**
- Call `find_easee_entities(self.hass)` for auto-detection
- Schema: `vol.Optional(CONF_CHARGER_STATUS_ENTITY): EntitySelector(EntitySelectorConfig(domain="sensor"))`, `vol.Optional(CONF_CHARGER_POWER_ENTITY): EntitySelector(EntitySelectorConfig(domain="sensor"))`
- Pre-fill with auto-detected values
- On submit: store EV config, proceed to `_create_entry()`

**_create_entry() helper:**
- Separate immutable `data` (Nordpool sensor + type) from mutable `options` (module toggles + entity configs)
- `data = {CONF_NORDPOOL_SENSOR, CONF_NORDPOOL_TYPE}`
- `options = {CONF_BATTERY_ENABLED, CONF_EV_ENABLED, CONF_SOC_ENTITY, CONF_BATTERY_POWER_ENTITY, CONF_CHARGER_STATUS_ENTITY, CONF_CHARGER_POWER_ENTITY}`
- `return self.async_create_entry(title="Energy Manager", data=data, options=options)`

**Stub OptionsFlow:**
- Implement `async_get_options_flow(cls, config_entry)` returning a stub `EnergyManagerOptionsFlow`
- The stub `async_step_init` just shows a placeholder form that returns `async_create_entry(data=self.config_entry.options)` unchanged
- Full options flow is Phase 6 scope, but the stub must exist so HA doesn't error when users click "Configure"
- Use try/except import pattern for `OptionsFlowWithReload` vs `OptionsFlowWithConfigEntry` for HA version compatibility (per PowerSaver pattern)

**CarSubentryFlowHandler(ConfigSubentryFlow):**
- Register via `async_get_supported_subentry_types(cls, config_entry)`: return `{SUBENTRY_TYPE_CAR: CarSubentryFlowHandler}` only if `config_entry.options.get(CONF_EV_ENABLED)` is True, else empty dict
- `async_step_user`: Show form with car config fields:
  - `vol.Required(CONF_CAR_NAME): TextSelector()` -- car friendly name
  - `vol.Optional(CONF_BATTERY_CAPACITY): NumberSelector(NumberSelectorConfig(min=10, max=200, step=1, unit_of_measurement="kWh"))` -- battery capacity
  - `vol.Optional(CONF_BATTERY_LEVEL_ENTITY): EntitySelector(EntitySelectorConfig(domain="sensor"))` -- battery level sensor
  - `vol.Optional(CONF_HOME_PLUGGED_ENTITY): EntitySelector(EntitySelectorConfig(domain=["sensor", "binary_sensor"]))` -- home+plugged sensor
- Call `find_car_integrations(self.hass)` for auto-detection, pre-fill first detected car if available
- On submit: `self.async_create_entry(title=user_input[CONF_CAR_NAME], data=user_input)`
- `async_step_reconfigure`: Load existing subentry data via `self._get_reconfigure_subentry()`, show form pre-filled with current values, on submit create updated entry
