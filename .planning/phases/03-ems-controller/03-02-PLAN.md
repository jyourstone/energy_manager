<objective>
Build the EMSCoordinator that orchestrates real-time EMS control, plus the config flow EMS step and auto-detection for SigenStor control entities.

Purpose: The EMSCoordinator is the bridge between the pure EMS calculation module (Plan 03-01) and the real world. It reads schedule data from BatteryScheduleCoordinator, reads real-time sensor data from HA, calls `compute_ems_state()` for decisions, sends control commands via HA service calls, and verifies commands took effect. The config flow EMS step collects the fuse rating and control entity IDs needed for this to work.

Output: EMSCoordinator in coordinator.py, EMSData dataclass, EMS constants in const.py, EMS config flow step, SigenStor EMS auto-detection.
</objective>

**EMSCoordinator class:**

Constructor parameters: `(hass, entry, battery_coordinator)`.
- Calls `super().__init__()` with name="Energy Manager EMS", update_interval=timedelta(seconds=EMS_UPDATE_INTERVAL_SECONDS), always_update=False.
- Stores `self._battery_coordinator = battery_coordinator`.
- Reads fuse_rating, EMS entity IDs from `entry.options`.
- Creates `self._pv_tracker = PVHysteresisTracker()` (import from ems_controller).
- Initializes `self._last_sent_mode: str | None = None` and `self._last_charge_limit: float | None = None` for change detection.
- Initializes `self._pending_verification: dict | None = None`.

**_async_setup():**
- Chain to BatteryScheduleCoordinator: `battery_coordinator.async_add_listener(self._handle_schedule_update)` with cleanup on unload.
- Register `async_track_state_change_event` listeners for L-current entity AND charger status entity (if configured) for immediate fuse-critical response. Clean up on unload.

**_handle_schedule_update callback:** `self.hass.async_create_task(self.async_request_refresh())`.
**_handle_fuse_update callback:** Same pattern.

**_async_update_data() -> EMSData:**
1. Read schedule data from `self._battery_coordinator.data`. If None, return EMSData with mode="unknown", all zeros/False.
2. Read real-time sensor values via `_read_float_state()`:
   - L-current from CONF_L_CURRENT_ENTITY (default 0.0 if unavailable)
   - PV power from CONF_PV_POWER_ENTITY (default 0.0)
   - Battery SOC from CONF_SOC_ENTITY (default 50.0)
3. Read car state: check if CONF_CHARGER_STATUS_ENTITY state is in ("awaiting_start", "charging", "ready_to_charge", "car_connected") => car_plugged_in=True. For car_scheduled, check if any car subentry exists with a schedule (for Phase 3, simplified: car_scheduled = entry.options.get(CONF_EV_ENABLED, False) -- the full implementation waits for Phase 4).
4. Update PV hysteresis tracker: `pv_active = self._pv_tracker.update(pv_power_w)`.
5. Call `compute_ems_state()` with all inputs.
6. Determine if mode changed: `result.target_mode != self._last_sent_mode`.
7. **Safe command ordering (from Research Pitfall 3):** If switching TO command_charging: send charge limit FIRST, then mode. If switching FROM command_charging: send mode FIRST, then zero limit.
8. Send commands via helper methods `_send_ems_mode()` and `_send_charge_limit()`.
9. If mode changed, schedule verification via `_schedule_verification()`.
10. Update `self._last_sent_mode` and `self._last_charge_limit`.
11. Check pending verification if exists.
12. Return EMSData.

**_read_float_state(entity_id, default) -> float:**
Helper that reads a sensor state, checks for unavailable/unknown, returns float or default. Same pattern as BatteryScheduleCoordinator._read_soc().

**_send_ems_mode(mode: str) -> bool:**
- Get entity_id from options.
- Check entity availability (state not None, not "unavailable"/"unknown").
- Map mode via EMS_MODE_MAP.
- Validate option is in entity's `options` attribute (if available) -- log error and skip if not found.
- Call `await self.hass.services.async_call("select", "select_option", {"entity_id": ..., "option": ...}, blocking=True)`.
- Log the command.
- Return True on success.

**_send_charge_limit(limit_kw: float) -> bool:**
- Get entity_id from options.
- Check availability.
- Clamp to [0.0, MAX_CHARGE_LIMIT_KW] before sending.
- Call `await self.hass.services.async_call("number", "set_value", {"entity_id": ..., "value": clamped}, blocking=True)`.
- Return True.

**_schedule_verification(entity_id: str, expected: str):**
- Store pending verification with entity_id, expected state, and timestamp.
- On next `_async_update_data()` call (30s later), check if the entity state matches expected.
- If verification fails after 2 cycles (60s), log warning. Clear pending verification.

**_check_verification() -> bool:**
- If no pending verification, return True.
- Read entity state. If matches expected, clear and return True.
- If time exceeded (>60s since sent), log warning, clear, return False.
- Otherwise return True (still waiting).
